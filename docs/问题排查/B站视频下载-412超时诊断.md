# B站视频下载失败诊断（AI Douyin 超时 + yt-dlp 412）

> 诊断日期：2026-06-14
> 状态：**根因已定位，方案待验证**（需用户提供 B站 Cookie）

---

## 问题现象

炼化 B站视频时，下载阶段两条路径全部失败：

```
22:48:29 ▶ 📥 下载视频  平台: B站视频
22:49:03 ▶ ⚠️ AI Douyin 失败，回退 yt-dlp
22:49:03 ℹ Python 脚本执行失败: download_video_candidates.py
            RuntimeError: all download URL candidates failed: 1: The read operation timed out
22:49:04 ✖ yt-dlp 下载失败: ERROR: [BiliBili] 13mV46AEwq: Unable to download webpage:
            HTTP Error 412: Precondition Failed
```

- AI Douyin 路径：`read timed out`（22:48:29 → 22:49:03 = **34 秒**，撞上脚本 30 秒 read timeout）
- yt-dlp 回退：`HTTP 412 Precondition Failed`

---

## 诊断过程

### 1. AI Douyin 候选 URL 结构（关键发现）

`download_video_candidates.py` 加诊断后打印的候选 URL：

```
https://ai-douyin.top9.cc/api/video/download-file?url=https%3A%2F%2Fwww.bilibili.com%2Fvideo%2FBV13mV46AEwq
```

**这不是预解析好的视频直链**，而是 AI Douyin 的**中转下载端点** `/api/video/download-file?url=<原始B站URL>`——它接收原始 B站 URL，**实时去 B站下载再转发**给客户端。

含义：resolve 接口（`/api/v1/video/download-url`）本身是成功的（200，给了中转端点），但这个中转端点实际下载时，AI Douyin 后端自己去 B站拉视频，**被 B站反爬卡住，34 秒没吐出数据** → urllib 超时。

### 2. 检查项汇总

| 检查项 | 结果 | 结论 |
|--------|------|------|
| AI Douyin 中转下 B站 | read timeout（34秒） | 中转后端也被 B站反爬挡，下不动 |
| yt-dlp 版本 | `2026.03.17`（3个月内） | **不是版本旧的问题** |
| yt-dlp 裸请求 B站（dump-json） | 同样 412 | 确认 B站风控，非偶发 |
| yt-dlp `--cookies-from-browser chrome` | `Failed to decrypt with DPAPI`（issue #10927） | Chrome App-Bound Encryption，yt-dlp 解不开 |
| yt-dlp `--cookies-from-browser edge` | `Could not copy Chrome cookie database`（issue #7271） | 同上 |
| yt-dlp `--cookies-from-browser firefox` | 未安装 firefox | — |

### 3. `412 Precondition Failed` 在 B站的含义

B站风控要求**登录态 Cookie**（`buvid3` / `SESSDATA` 等）。裸 yt-dlp 没带 Cookie 就被挡，**最新版也一样**。这是 B站主动反爬，不是 bug。

---

## 根因结论

**B站视频本身难下，两条路径都被 B站反爬挡：**

1. **AI Douyin 对 B站完全无效**——它的中转代理（`/api/video/download-file`）是给抖音/小红书设计的，B站反爬它也绕不过。还白扣 1 积分（resolve 费）+ 浪费 34 秒超时。
2. **yt-dlp 裸请求被 412**——缺登录态 Cookie。
3. **`--cookies-from-browser` 走不通**——Chrome 新版 App-Bound Encryption（yt-dlp 已知 issue #10927）。

**唯一可行路径：手动给 yt-dlp 提供 B站 Cookie（已解密的 cookies.txt 或 SESSDATA）。**

---

## 解决方案（待验证 → 待实现）

### 步骤 1：用户导出 B站 Cookie（待用户操作）

**方式 A — cookies.txt（推荐，最稳）：**
1. Chrome/Edge 打开 bilibili.com 并**确保已登录**
2. 装插件 **"Get cookies.txt LOCALLY"**（Chrome 商店，开源）
3. 插件 → Export → 得到 `bilibili.com_cookies.txt`
4. 放到 `D:\Project\myriad-mind-app\bilibili_cookies.txt`（或任意路径）

**方式 B — SESSDATA 单值（可能不够）：**
- F12 → Application → Cookies → bilibili.com → 复制 `SESSDATA` 值
- B站现在常要 `buvid3` 一起，单独 SESSDATA 不一定过

### 步骤 2：验证 cookies.txt 能否解 412（待做）

```bash
yt-dlp --cookies <cookie文件路径> --no-playlist --socket-timeout 15 --dump-json "https://www.bilibili.com/video/BV13mV46AEwq"
```

能输出 JSON = 方案成立，进入步骤 3。

### 步骤 3：改代码（验证通过后）

- **`pipeline.rs:319-338`** B站分支改成**优先 yt-dlp，AI Douyin 兜底**（省积分 + 省 34 秒超时；当前是反过来的）
- **config schema** 加 `bilibili_cookies_path` 字段（cookies.txt 路径）
- **`download_video_ytdlp`（pipeline.rs:1848）** B站时透传 `--cookies <path>`
- **`.gitignore`** 加 cookie 文件（敏感，不入 git）

## 关联

- **视频下载缓存机制**：已实现 `run_video_pipeline` 下载前查 `video.mp4` 命中跳过下载省积分。但**对这个 500/超时场景帮不上**——下载失败 → `video.mp4` 没缓存成 → 下次还得 resolve（扣积分）。如需反复测 500 不扣分，要再加 resolve 结果缓存（`download_url.json` 命中跳过 resolve）。
- **AI Douyin 主战场是抖音**：文档示例是 `douyin.com/video/...`，域名 `ai-douyin`。B站不是它强项，B站本就不该走它。
- **诊断代码已在脚本里**：`download_video_candidates.py` 加了 HTTPError 时打印 status/Content-Type/Server/body，下次跑失败视频能直接看到 AI Douyin 返回的真实错误体。
