**关键原则**:
- `components/ui/` — 纯 UI 原语，无业务逻辑，无 Tauri 依赖
- `components/<domain>/` — 业务组件，可依赖 hooks 和 api
- `hooks/` — 纯逻辑，返回数据 + 操作方法，不渲染 JSX
- `lib/` — 纯工具函数，不依赖 React
- `api.ts` — 所有 Tauri 调用的唯一出口，含浏览器 mock

## 2. 文件命名

| 类型 | 命名规则 | cc-switch 示例 |
|------|----------|----------------|
| UI 原语（单字） | 小写 | `button.tsx`, `input.tsx` |
| UI 原语（多字） | kebab-case | `mode-toggle.tsx`, `scroll-area.tsx` |
| 业务组件 | PascalCase | `SettingsPage.tsx`, `ProviderList.tsx`, `ConfirmDialog.tsx` |
| Hook 文件 | camelCase + `use` 前缀 | `useSettings.ts`, `useProxyStatus.ts` |
| API 模块 | camelCase | `api.ts`, `settings.ts` |
| 工具函数 | camelCase | `utils.ts`, `deepClone.ts`, `errorUtils.ts` |
| 类型文件 | camelCase | `pipeline.ts` |
| CSS 入口 | PascalCase (匹配入口) | `App.css`, `index.css` |
| 目录 | kebab-case | `components/settings/`, `lib/query/` |

**文件命名结论**: 完全遵循 cc-switch 模式 —— UI 原语小写/kebab，业务组件 PascalCase，hook camelCase。（大衍决桌面端组件不超过 20 个，命名一致性比规模更重要。）

## 3. 组件模板

### 3.1 通用 UI 组件 (`components/ui/`)

**模式: `React.forwardRef` + `cn()` + 命名导出**

```tsx
import * as React from "react";
import { cn } from "@/lib/utils";

// ---- Variants (CSS class map) ----

const BUTTON_VARIANTS = {
  default: "btn-default",
  primary: "btn-primary",
  ghost: "btn-ghost",
  danger: "btn-danger",
} as const;

const BUTTON_SIZES = {
  default: "btn-md",
  sm: "btn-sm",
  lg: "btn-lg",
  icon: "btn-icon",
} as const;

// ---- Props ----

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: keyof typeof BUTTON_VARIANTS;
  size?: keyof typeof BUTTON_SIZES;
  loading?: boolean;
}

// ---- Component ----

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant = "default", size = "default", loading, disabled, children, ...props }, ref) => (
    <button
      className={cn(
        "btn-base",
        BUTTON_VARIANTS[variant],
        BUTTON_SIZES[size],
        loading && "btn-loading",
        className,
      )}
      disabled={disabled || loading}
      ref={ref}
      {...props}
    >
      {loading && <span className="btn-spinner" />}
      {children}
    </button>
  ),
);
Button.displayName = "Button";

export { Button, type ButtonProps };
```

### 3.2 业务组件 (`components/<domain>/`)

**模式: 命名函数 + Props interface + `useCallback`**

```tsx
import { useCallback } from "react";
import { Button } from "@/components/ui";
import { usePipeline } from "@/hooks/usePipeline";

// ---- Props ----

interface InputAreaProps {
  config: MyriadMindConfig;
  onComplete: () => void;
}

// ---- Component ----

export function InputArea({ config, onComplete }: InputAreaProps) {
  const { submit, status, progress, processing } = usePipeline(config);

  const handleSubmit = useCallback(() => {
    submit(inputUrl);
  }, [submit, inputUrl]);

  return (
    <div className="input-area">
      {/* ... */}
      <Button onClick={handleSubmit} loading={processing}>
        炼化
      </Button>
    </div>
  );
}
```

### 3.3 导出规范

cc-switch 源码中两种模式并存：

| 组件类型 | 导出方式 | cc-switch 示例 |
|----------|----------|----------------|
| `components/ui/` 原语 | `export { Button }` 命名导出 | `button.tsx`, `input.tsx` (shadcn 风格) |
| 业务/页面级组件 | `export default` + `export function` 混用 | `SettingsPage.tsx` 用命名，`PromptPanel.tsx` 用 default |

**大衍决约定**:
- `components/ui/` → **命名导出** `export { Button }`（保持 shadcn 风格）
- 其他业务组件 → 两种均可，**同一文件内保持一致**即可

### 3.4 核心规则

1. **Props interface 在组件上方** — 命名 `{ComponentName}Props`
2. **事件处理用 `useCallback`** — 作为 props 传递时必须
3. **`cn()` 合并 className** — 接收外部 `className` 时用 `cn("base", className)`
4. **`.displayName`** — forwardRef 组件必须设置
5. **App.tsx ≤ 100 行** — 只做布局 + 视图路由 + Provider 组合

## 4. 样式方案

### 4.1 约束

| 层 | 样式方案 | 说明 |
|----|----------|------|
| `packages/ui` | **纯 CSS classes + CSS Variables** | ❌ 禁止 Tailwind（保持零依赖） |
| `apps/desktop` | CSS Variables + App.css classes | 可引入 Tailwind，但当前保持轻量 |
| `apps/mobile` | React Native StyleSheet | 独立方案 |

### 4.2 CSS Variables 命名规范

```css
:root {
  /* 色板 — 直接色值，不是 HSL 三值 */
  --bg-root: #0f0f1a;
  --bg-surface: #1a1a2e;
  --bg-elevated: #1e1e36;
  --border: #2a2a4a;
  --border-hover: #3a3a5a;
  --text: #e0e0f0;
  --text-secondary: #a0a0c0;
  --text-muted: #666;
  --primary: #6366f1;
  --primary-hover: #818cf8;
  --primary-muted: rgba(99, 102, 241, 0.15);
  --accent: #c0a0ff;
  --green: #4ade80;
  --yellow: #facc15;
  --red: #f87171;
  --radius: 10px;
}
```

**命名规则**:
- `--bg-*` — 背景色（root < surface < elevated）
- `--text-*` — 文字色（text < secondary < muted）
- `--border-*` — 边框色
- `--primary-*` — 主色调
- `--{color}` — 语义色（green/yellow/red）
- `--radius` — 全局圆角

**不做**: 像 cc-switch 那样用 HSL 三值（`0 0% 100%`），为什么？我们的 packages/ui 没有 Tailwind，不需要 `hsl(var(--xxx))` 这种中间层。直接用色值更直观。

### 4.3 CSS 类命名规范

**BEM 风格**，用 `-` 连接层级：

```css
/* Block */
.log-panel { }
/* Block__Element */
.log-panel-header { }
.log-panel-body { }
/* Block--Modifier */
.log-line-divider { }
.log-line-step { }
/* State */
.nav-btn-active { }
.settings-tab-active { }
```

**禁止**: CSS Modules（`.module.css`）——统一用全局 CSS + BEM 命名防冲突。项目规模可控，不需要 CSS Modules 的额外心智负担。

### 4.4 `cn()` 工具函数

```ts
// lib/utils.ts
export function cn(...classes: (string | false | null | undefined)[]): string {
  return classes.filter(Boolean).join(" ");
}
```

**注意**: 这是 cc-switch `cn()` 的简化版。因为没有 Tailwind → 不需要 `twMerge`。只做条件拼接。

用法：
```tsx
<div className={cn("log-line", `log-line-${type}`, streaming && "log-streaming")}>
```

## 5. Hooks 规范

### 5.1 模式

```ts
import { useState, useCallback, useEffect } from "react";

// ---- 类型 ----

interface UsePipelineOptions {
  config: MyriadMindConfig;
}

interface UsePipelineResult {
  submit: (input: string) => Promise<void>;
  cancel: () => void;
  status: string | null;
  progress: number;
  processing: boolean;
  logs: LogEntry[];
  streamingText: string;
}

// ---- Hook ----

export function usePipeline({ config }: UsePipelineOptions): UsePipelineResult {
  const [status, setStatus] = useState<string | null>(null);
  const [progress, setProgress] = useState(0);
  const [processing, setProcessing] = useState(false);
  // ...

  const submit = useCallback(async (input: string) => {
    // ...
  }, [config]);

  const cancel = useCallback(() => {
    // ...
  }, []);

  return {
    submit,
    cancel,
    status,
    progress,
    processing,
    logs,
    streamingText,
  };
}
```

### 5.2 规则

1. **一个 hook 一个文件** — 文件名 `use{PascalCase}.ts`
2. **Props 用 interface** — `Use{HookName}Options`
3. **返回用 interface** — `Use{HookName}Result`
4. **返回 plain object** — 不渲染 JSX
5. **事件处理用 `useCallback`** — 返回给组件的方法必须 memo
6. **禁止 hook 中调用 hook 形成深层嵌套** — 最多 2 层组合（如 cc-switch `useSettings` 组合 3 个子 hook）

## 6. 类型系统

### 6.1 分层

| 层 | 位置 | 内容 |
|----|------|------|
| 共享核心类型 | `packages/core/src/types.ts` | MyriadMindConfig, NoteMeta, DashboardData, ... |
| 共享 Zod Schema | `packages/core/src/schema.ts` | ConfigSchema, ... |
| 桌面端特有类型 | `apps/desktop/src/types/` | DepResult, PipelineProgress, ... |
| 组件 Props | 组件文件内 | `interface XxxProps` |

### 6.2 规则

1. **共享类型在 `@myriad-mind/core`** — 桌面端和移动端都 import 同一份
2. **组件 Props 定义在组件文件内** — 不单独拆类型文件
3. **`interface` 优先** — 对象形状用 interface；联合类型/映射类型用 type
4. **Props 命名**: `{ComponentName}Props`
5. **Hook 返回命名**: `Use{HookName}Result`

## 7. API 层

### 7.1 模式

```ts
// api.ts — 所有 Tauri invoke/listen 的唯一出口

// ---- 配置 ----
export async function readConfig(): Promise<string> { ... }
export async function writeConfig(json: string): Promise<void> { ... }

// ---- 管线 ----
export async function executePipeline(input: string, mode: string, ...): Promise<PipelineResult> { ... }
export function listenPipelineProgress(callback: (e: PipelineProgress) => void): () => void { ... }

// ---- 密钥链 ----
export async function checkKeychainEntry(service: string, namespace: string): Promise<{exists: boolean}> { ... }
```

### 7.2 规则

1. **所有 Tauri 调用走 `api.ts`** — 不直接在组件中 `invoke()`
2. **必须有浏览器 mock** — `isTauri()` 检测 → 返回模拟数据，方便前端独立开发
3. **listen() 返回 unsubscribe 函数** — 调用方在 cleanup 时调用
4. **错误统一处理** — 不要在 api.ts 里吞掉错误，抛给上层 hook 处理

## 8. 导入约定

### 8.1 路径别名

```json
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}
```

### 8.2 导入顺序

```tsx
// 1. React 核心
import { useState, useCallback, useEffect } from "react";

// 2. 第三方库
import { invoke } from "@tauri-apps/api/core";

// 3. 共享包
import { type MyriadMindConfig, classifyInput } from "@myriad-mind/core";

// 4. 共享 UI 包
import { Button, Input } from "@myriad-mind/ui";

// 5. 项目内模块 (用 @/ 别名)
import * as api from "@/api";
import { usePipeline } from "@/hooks/usePipeline";
import { cn } from "@/lib/utils";
import { LogPanel } from "@/components/log/log-panel";

// 6. 类型导入
import type { PipelineProgress } from "@/types/pipeline";

// 7. 样式（最后）
import "./App.css";
```

**规则**: 用 `@/` 别名导入项目内模块，禁止 `../../../` 相对路径。

## 9. 禁止事项

| ❌ 禁止 | ✅ 替代 |
|----------|--------|
| `packages/ui` 中引入 Tailwind | 纯 CSS classes + CSS Variables |
| 组件内直接 `invoke()` | 封装到 `api.ts` |
| `../../../` 深相对路径 | `@/` 别名 |
| inline `style={{}}` 超过 3 个属性 | 抽取为 CSS class |
| App.tsx 超过 100 行 | 拆分为 hooks + 子组件 |
| 业务逻辑写在组件内 | 抽到 `hooks/` 或 `lib/` |
| CSS Modules (`.module.css`) | 全局 CSS + BEM 命名 |
| 硬编码色值 | CSS Variables |
| 类型和组件放在不同文件 | Props interface 写在组件文件内 |

## 10. App.tsx 拆分标准

**当前问题**: App.tsx ~437 行，混合了所有逻辑。

**目标**: App.tsx ≤ 60 行，只做布局 + 视图路由。

**拆分方法**:

| 逻辑块 | 移入 | 行数 |
|--------|------|------|
| 配置加载/保存 | `hooks/useConfig.ts` | ~40 |
| 管线执行 + 日志 | `hooks/usePipeline.ts` | ~180 |
| Tauri 检测 | `lib/platform.ts` | ~10 |
| Keychain 适配器 | `hooks/useKeychain.ts` 或内联 | ~10 |
| 输入页 UI | `components/input/input-area.tsx` | ~80 |
| 侧边栏导航 | `components/layout/sidebar.tsx` | ~30 |
| NavButton | `components/layout/nav-button.tsx` | ~20 |
| **App.tsx 剩余** | **仅 layout + view 路由** | **~60** |

**拆分后 App.tsx 形态**:
```tsx
import { useConfig } from "@/hooks/useConfig";
import { Sidebar } from "@/components/layout/sidebar";
import { InputView } from "@/components/input/input-view";
import { DashboardView } from "@/components/dashboard/dashboard-view";
import { SettingsView } from "@/components/settings/settings-view";

export function App() {
  const { view, setView, config, saveConfig, firstLaunch, finishWizard } = useConfig();

  return (
    <div className="app-root">
      <Sidebar activeView={view} onNavigate={setView} />
      <main className="main-content">
        {view === "input"    && <InputView     config={config} />}
        {view === "dashboard" && <DashboardView config={config} />}
        {view === "settings"  && <SettingsView  config={config} onSave={saveConfig} firstLaunch={firstLaunch} onFinishWizard={finishWizard} />}
      </main>
    </div>
  );
}
```
