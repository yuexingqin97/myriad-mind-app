# 发布打包流程

> 目标：先把 Windows 桌面版发布跑通，并优先内置 FFmpeg / FFprobe，减少普通用户配置成本。  
> 当前阶段建议发布为 `v0.1.0-alpha.x` 草稿 Release，人工验证后再公开。

---

## 一、发布目标

v1 初期不要追求全平台。先建立一条稳定链路：

```text
Windows 构建
→ 内置 FFmpeg
→ 生成 Tauri 安装包
→ GitHub Draft Release
→ 手动验证
→ 发布
```

用户版目标：

- 用户不需要安装 Node.js。
- 用户不需要安装 Rust。
- 用户不需要安装 pnpm。
- 用户优先只配置 DeepSeek API Key。
- 视频处理优先使用随包附带的 FFmpeg。

开发者才需要：

- Node.js 24+
- pnpm
- Rust 1.93+
- Python 3.9+

## 二、FFmpeg 打包策略

### 2.1 推荐方案

第一版用 Tauri `resources` 打包 FFmpeg。

原因：

- 实现简单。
- 不需要 sidecar target triple 命名。
- 适合 `ffmpeg.exe` / `ffprobe.exe` 这种工具型二进制。
- Rust 端可以按资源路径找到它，再用 `Command` 调用。

Tauri 官方文档说明，`resources` 用于把前端产物之外、无法内联进二进制或体积较大的额外文件放进应用包。

### 2.2 目录建议

```text
apps/desktop/src-tauri/resources/
├── bin/
│   └── windows/
│       ├── ffmpeg.exe
│       └── ffprobe.exe
└── licenses/
    ├── ffmpeg-LICENSE.txt
    └── ffmpeg-NOTICE.md
```

### 2.3 `tauri.conf.json` 配置

建议把整个 `resources/` 目录打进去：

```json
{
  "bundle": {
    "resources": [
      "resources/"
    ]
  }
}
```

也可以显式列文件：

```json
{
  "bundle": {
    "resources": [
      "resources/bin/windows/ffmpeg.exe",
      "resources/bin/windows/ffprobe.exe",
      "resources/licenses/ffmpeg-LICENSE.txt",
      "resources/licenses/ffmpeg-NOTICE.md"
    ]
  }
}
```

### 2.4 Rust 检测顺序

FFmpeg 查找顺序建议统一为：

```text
1. 内置资源路径
2. 用户在设置中指定的路径
3. 系统 PATH
4. 未找到，提示安装或重新检测
```

设置页显示文案：

```text
FFmpeg：已就绪 · 使用内置版本
```

如果内置版本不可用但系统 PATH 可用：

```text
FFmpeg：已就绪 · 使用系统版本
```

### 2.5 许可证注意

FFmpeg 构建可能是 LGPL 或 GPL，取决于启用的编译选项。

发布前必须确认下载来源和许可证：

- 优先选择 LGPL 构建。
- 保留 FFmpeg 许可证文件。
- Release 页面说明随包附带 FFmpeg。
- README / About 页保留第三方组件声明。

Release 说明示例：

```markdown
本版本随包附带 FFmpeg / FFprobe，用于本地视频、音频和关键帧处理。
FFmpeg 版权和许可证归 FFmpeg 项目及其贡献者所有。
详见应用包内 licenses/ffmpeg-LICENSE.txt。
```

## 三、本地打包流程

### 3.1 准备

```powershell
pnpm install
```

确认资源存在：

```text
apps/desktop/src-tauri/resources/bin/windows/ffmpeg.exe
apps/desktop/src-tauri/resources/bin/windows/ffprobe.exe
```

### 3.2 本地开发验证

```powershell
cd apps/desktop
pnpm tauri dev
```

验证项：

- 设置页 FFmpeg 显示“使用内置版本”。
- 依赖检测不要求用户安装系统 FFmpeg。
- 本地视频 / 音频相关流程能调用内置 FFmpeg。
- 打开配置向导时，FFmpeg 状态为就绪。

### 3.3 本地生产构建

```powershell
cd apps/desktop
pnpm tauri build
```

构建产物通常在：

```text
apps/desktop/src-tauri/target/release/bundle/
```

需要检查：

- `.msi` 安装包是否生成。
- `.exe` / NSIS 包是否生成，取决于 Tauri bundle 配置。
- 安装后应用能找到内置 FFmpeg。

## 四、版本号规则

当前建议使用预发布版本：

```text
v0.1.0-alpha.1
v0.1.0-alpha.2
v0.1.0-beta.1
v1.0.0
```

规则：

| 类型 | 示例 | 用途 |
|------|------|------|
| alpha | `v0.1.0-alpha.1` | 内测，功能未完整 |
| beta | `v0.1.0-beta.1` | 主流程可跑，开始收敛体验 |
| stable | `v1.0.0` | 面向普通用户 |

发布前同步更新：

- `README.md`
- `CHANGELOG.md`
- `docs/需求与排期.md`
- `package.json` / `tauri.conf.json` 中的版本号

## 五、GitHub Actions 发布流程

### 5.1 触发方式

用 Git tag 触发：

```text
git tag v0.1.0-alpha.1
git push origin v0.1.0-alpha.1
```

### 5.2 Workflow 文件

新增：

```text
.github/workflows/release.yml
```

建议第一版只构建 Windows：

```yaml
name: Release

on:
  push:
    tags:
      - "v*"

permissions:
  contents: write

jobs:
  release-windows:
    runs-on: windows-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 10

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: pnpm

      - name: Setup Rust
        uses: dtolnay/rust-toolchain@stable

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build and publish Tauri app
        uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          projectPath: apps/desktop
          tagName: ${{ github.ref_name }}
          releaseName: "大衍决 ${{ github.ref_name }}"
          releaseBody: |
            这是大衍决 Windows Alpha 测试版本。

            详细变化请查看 CHANGELOG.md。
          releaseDraft: true
          prerelease: true
```

说明：

- `releaseDraft: true`：先生成草稿 Release，人工检查后再发布。
- `prerelease: true`：alpha / beta 阶段标记为预发布。
- `permissions.contents: write`：允许 workflow 创建 Release 并上传产物。

## 六、Release 页面内容模板

```markdown
# 大衍决 v0.1.0-alpha.1

> Alpha 测试版本，建议用于功能验证，不建议作为长期生产数据唯一入口。

## 下载

- Windows 安装包：见 Assets

## 本版重点

- 内置 FFmpeg / FFprobe，减少视频处理配置。
- 配置目录统一为 `~/.myriad-mind-app/`。
- 支持 DeepSeek API Key 配置。
- 炼化页基础流程与设置页健康检查。

## 使用前需要

- DeepSeek API Key
- 可选：AI Douyin / TikHub Key

## 已知问题

- Python / faster-whisper 暂未内置。
- 视频解析能力依赖用户自己的第三方 API Key。
- 当前为 Alpha 版本，部分流程仍可能需要手动配置。

## 第三方组件

本版本随包附带 FFmpeg / FFprobe。
FFmpeg 版权和许可证归 FFmpeg 项目及其贡献者所有。
详见应用包内 `licenses/ffmpeg-LICENSE.txt`。
```

## 七、发布前检查清单

### 7.1 代码与文档

- [ ] `README.md` 普通用户安装说明不再要求 Node / Rust / pnpm。
- [ ] `README.md` 开发者章节保留 Node / Rust / pnpm。
- [ ] `CHANGELOG.md` 写明本版变化。
- [ ] `docs/需求与排期.md` 标记当前版本已完成项。
- [ ] `tauri.conf.json` 版本号正确。
- [ ] `package.json` 版本号正确。

### 7.2 FFmpeg

- [ ] `ffmpeg.exe` 已放入 `resources/bin/windows/`。
- [ ] `ffprobe.exe` 已放入 `resources/bin/windows/`。
- [ ] 许可证文件已放入 `resources/licenses/`。
- [ ] 设置页能显示内置 FFmpeg 状态。
- [ ] 真实视频处理调用的是内置 FFmpeg。
- [ ] 没有把 FFmpeg 放进 git 忽略规则导致 Release 缺文件。

### 7.3 构建

- [ ] 本地 `pnpm tauri dev` 能启动。
- [ ] 本地 `pnpm tauri build` 能生成安装包。
- [ ] GitHub Actions 能创建 Draft Release。
- [ ] Release Assets 中包含 Windows 安装包。

### 7.4 安装验证

建议在 Windows Sandbox 或干净虚拟机验证：

- [ ] 未安装 Node.js 时 App 可启动。
- [ ] 未安装 Rust 时 App 可启动。
- [ ] 未安装 pnpm 时 App 可启动。
- [ ] 未安装系统 FFmpeg 时 App 仍显示 FFmpeg 就绪。
- [ ] 配置目录创建在 `~/.myriad-mind-app/`。
- [ ] DeepSeek Key 不写入 `config.json`。
- [ ] 设置页依赖检测不报原始 `invoke` 错误。
