# 配置系统设计

> 本文是大衍决**配置子系统的权威设计文档**，整合自原《配置引导流程设计》《UI修为与设置界面设计》中所有配置相关逻辑，并与当前代码实现对齐。
> 两份原文档保留作历史参考，配置存储/保存机制以本文为准。

## 一、设计目标

配置子系统要回答四个问题：

1. **能不能跑**：本机 Python / FFmpeg / yt-dlp / GPU 依赖是否就绪。
2. **能不能生成**：DeepSeek API Key（主模型 V4 Pro）是否可用。
3. **输出在哪**：笔记输出目录、临时文件策略。
4. **生成什么**：笔记内容偏好（关键帧、Mermaid、术语表等）。

设计原则：配置不是「大表单」，而是「可用性中心」——让用户一眼看到缺什么、缺了影响什么、怎么补。

## 二、存储模型

### 存储位置

```
~/.myriad-mind-app/config.json
```

- `~` 解析为当前用户主目录（Windows 用 `%USERPROFILE%`，其他平台 `$HOME`），所有平台统一。
- **明文 JSON**，含 API Key（DeepSeek Key、AI Douyin Key）。
- **不入 git**（`.gitignore` 忽略 `config.json`），用户自行保管文件安全。
- 个人桌面工具、单用户场景，不做多用户隔离、不做加密。
- 配置文件带版本号（`version: 1`），支持未来迁移。

### 为什么是 config.json 明文（不是 OS 密钥链）

早期设计曾计划把 API Key 存 OS 密钥链（Windows Credential Manager / macOS Keychain），配置其他字段存 JSON。实际实现简化为**全部存 config.json 明文**，理由：

- 单用户桌面工具，OS 密钥链的隔离价值不大，反而引入跨平台凭据读写复杂度与失败面。
- 用户可直观看到/备份/迁移配置文件（复制 `config.json` 到新机器即可）。
- 选云盘目录时连配置一起同步。

> ⚠️ 历史：原《配置引导流程设计》《UI修为与设置界面设计》中「API Key 存 OS 密钥链、不写 config.json」的描述**已过时**，以本文为准。

## 三、配置字段清单（ConfigSchema）

定义在 `packages/core/src/schema.ts`，用 Zod 校验。前端 `MyriadMindConfig` 类型、`DEFAULT_CONFIG` 默认值、配置校验均以此为准。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `version` | `1` | `1` | 配置版本号（迁移用） |
| `python_path` | `string` | `""` | Python 解释器路径，留空=自动探测 |
| `deepseek_api_key` | `string` | `""` | **必填**，笔记生成主模型 Key |
| `ai_douyin_api_key` | `string` | `""` | 可选，视频解析 Key |
| `asr` | object | — | 语音识别（见下） |
| `video` | object | — | 视频解析（见下） |
| `features` | object | — | 笔记内容偏好（见下） |
| `keyframes` | object | — | 关键帧参数 |
| `output` | object | — | 输出与文件管理（见下） |
| `post_process` | object | — | 收尾操作 |

### asr（语音识别）

```
backend: "faster-whisper" | "volcengine"
faster_whisper?: { model_size, device, compute_type? }
volcengine?: { token_keyring_id, appid }
```

> **当前实现**：后端管线只有 faster-whisper 本地转写（`transcribe_faster_whisper.py`）。**火山引擎云端 ASR 后端未实现**，UI 已移除该选项。schema 保留 `volcengine?` 字段以兼容老配置，但不可选。

### video（视频解析）

```
provider: "ai-douyin" | "tikhub"
```

> **当前实现**：后端只接入 AI Douyin（`resolve_via_ai_douyin` + `download_douyin_video`）。**TikHub 后端未实现**，UI 保留切换按钮但选 TikHub 无效。

### features（笔记内容）

```
keyframes, mermaid, resources, comments, reading_info, estimation: boolean
screenshot_review?: { enabled, mode, max_review_frames, min_score, max_selected }
tutorial_detection: boolean
```

### output（输出与文件管理）

```
note_dir: string         // 笔记输出目录，建议必填
cleanup_temp: boolean    // 自动清理临时文件；关闭=保留 temp（调试/缓存用）
note_metadata: boolean   // 笔记末尾元信息
debug_metadata: boolean  // 调试元信息
```

> 💡 `cleanup_temp` 同时是**视频下载缓存开关**：关闭它（保留 temp）后，`run_video_pipeline` 下载前会检查 `video.mp4` 是否已存在，命中即跳过下载（省 AI Douyin 积分）。详见 [[视频下载缓存]] 机制。

### 已从 UI 移除的字段

以下字段**前端不再提供输入框**（后端管线未实现，避免「填了没人用」的误导）：

- `tikhub_token` / `volcengine_token` / `claude_api_key`：原本通过即时写路径存 config.json 顶层，但后端从不读取，已连同输入框一并移除。将来接入时再加回 schema + UI。

## 四、保存机制

### 核心原则：统一保存，无即时单独写

配置变更**不再即时单独写盘**（历史上有过 API Key 即时写 keychain 的机制，已移除）。所有配置走两条统一路径：

| 场景 | 保存方式 | 触发 |
|------|----------|------|
| **设置页**（日常调整） | debounce 自动保存 | 修改后停手 ~800ms 自动落盘 |
| **配置向导**（首次/重新引导） | 统一保存 | 最后一步「完成并保存」一次性落盘 |

### 设置页 debounce 自动保存（数据源统一在 useConfig）

设置页**不持有 local state**——`config` 和 `update` 都由父级 `useConfig` 提供，改动**即时进 App 内存**，由 `useConfig` 的 debounce effect 统一写盘。这样切换到向导/其他视图时不会丢失未保存的改动。

`apps/desktop/src/hooks/useConfig.ts`：

1. `update(key, value)` → `setConfig(c => ({ ...c, [key]: value }))`（即时改 App 内存）。
2. `useEffect` 监听 `config` 变化，防抖 800ms 后 `api.writeConfig`。
3. 首次 mount 跳过（避免 `DEFAULT_CONFIG` 回写覆盖磁盘）；`saveConfig` 已自行写盘时跳过本次（`skipNextAutosave`）。

```ts
const update = useCallback(<K extends keyof MyriadMindConfig>(key: K, value: MyriadMindConfig[K]) => {
  setConfig((c) => ({ ...c, [key]: value }));
}, []);

useEffect(() => {
  if (initialMount.current) { initialMount.current = false; return; }
  if (skipNextAutosave.current) { skipNextAutosave.current = false; return; }
  const timer = window.setTimeout(() => api.writeConfig(JSON.stringify(config)), 800);
  return () => window.clearTimeout(timer);
}, [config]);
```

`SettingsPage` 只用传入的 `config` + `update`，无 local state、无保存提示（autosave 静默）。

### 配置向导统一保存

`packages/ui/src/ConfigWizard.tsx`：七步流程中每步只改 local state，**不落盘**；最后一步（review）的「🚀 完成并开始炼化」或「💾 保存后留在设置」才调 `onSave(config, action)` 一次性写盘。中途取消不写半成品。

### 后端命令（`apps/desktop/src-tauri/src/commands/config.rs`）

| 命令 | 作用 |
|------|------|
| `get_config_info` | 返回 config.json 路径 + 是否存在 + 是否首启 |
| `is_first_launch` | config.json 不存在则 true |
| `read_config` | 读全量配置（无文件返回 `{}`） |
| `write_config` | **全量写**（原子写：先 `.tmp` 再 rename） |
| `reset_config` | 删除 config.json（重置） |

Rust 内部函数（非 Tauri 命令）：
- `read_config_value(key)`：同步读单字段，供 `engine.rs`（读 `deepseek_api_key`）、`pipeline.rs`（读 `ai_douyin_api_key`）使用。

### SECRET_FIELDS 空值保护

`write_config` 全量写入时，对敏感字段做保护：

```rust
const SECRET_FIELDS: &[&str] = &["deepseek_api_key", "ai_douyin_api_key"];
```

逻辑：新值（前端传来的 config state）为空时，**保留磁盘已有值**，避免前端 state 未同步把已配置的 Key 覆盖成空。

典型场景：首启路径 `state = DEFAULT_CONFIG`（Key 为空），用户走完向导保存 → 保护生效，不覆盖磁盘已有 Key。

## 五、前端数据流

```
启动 → useConfig.useEffect → api.readConfig() → setConfig(merge DEFAULT + 磁盘值)
                                    ↓
设置页 SettingsPage(config, update) → update(key,value) 即时改 useConfig.config（App 内存）
                                    ↓
                        useConfig debounce effect（800ms）→ api.writeConfig
                                    ↓
                          Rust write_config（含 SECRET_FIELDS 空值保护）

向导 ConfigWizard → 走自己的 local state → 最后一步「完成并保存」→ useConfig.saveConfig → 立即 writeConfig
```

- `useConfig`（`apps/desktop/src/hooks/useConfig.ts`）：唯一数据源。持有 `config` state，启动从磁盘加载，提供 `update`（设置页用，即时改 + debounce 自动写盘）和 `saveConfig`（向导用，立即写盘）。
- `SettingsView`（`apps/desktop/src/components/settings/SettingsView.tsx`）：在 `SettingsPage`（常规，透传 `update`）和 `ConfigWizard`（向导，透传 `onSave`）之间切换。
- 关键：设置页和向导看**同一份** App 内存 config，切换不丢改动。

## 六、API Key 清单

| Key | 必填 | 用途 | 后端读取 |
|-----|------|------|----------|
| **DeepSeek API Key** | ✅ 必填 | 笔记生成主模型（V4 Pro / Flash） | `engine.rs::read_config_value("deepseek_api_key")` |
| **AI Douyin API Key** | 可选 | B站/抖音/小红书视频解析 | `pipeline.rs::read_config_value("ai_douyin_api_key")` |

安全规则：
- 明文存 config.json，**不在日志/错误/进度事件中回显原文**。
- UI 只显示脱敏值（前 8 位 + 后 4 位）。
- 应用不内置任何 Key，用户自行在 platform.deepseek.com / ai-douyin.top9.cc 申请。

## 七、配置引导流程（ConfigWizard）

七步：`welcome → deps → keys → processing → output → features → review`

| 步骤 | 内容 | 阻塞条件 |
|------|------|----------|
| welcome | 选择使用路径（在线视频/本地媒体/网页文章/代码） | — |
| deps | 系统依赖检查（Python/FFmpeg/faster-whisper/yt-dlp/GPU） | 缺必需依赖（按 intent） |
| keys | 配置 DeepSeek Key（必填）+ AI Douyin Key（可选） | — |
| processing | ASR（faster-whisper）+ 视频解析策略 | — |
| output | 输出目录（必填）+ 临时文件清理 + 元信息 | 输出目录为空 |
| features | 笔记内容偏好 + 关键帧参数 | — |
| review | 配置摘要 → 完成并保存 | — |

入口：
- **自动引导**：首启（config.json 不存在）→ `firstLaunch=true` → 自动打开向导。
- **手动引导**：设置页「打开配置向导」按钮。

中断恢复：中途取消不写半成品；已保存的 Key（在磁盘）保留。

## 八、首启判定与配置状态（setupStatus 状态机）

`useConfig` 维护 `setupStatus` 状态机，取代单一的 `firstLaunch`：

```ts
type SetupStatus =
  | "checking"            // 启动中
  | "ready"              // config.json 存在 + Schema 通过 + DeepSeek Key 非空
  | "needs_config"       // config.json 不存在，或缺 DeepSeek Key
  | "invalid_config"     // config.json 存在但 Schema 校验失败
  | "backend_unavailable"; // 非 Tauri 环境（浏览器 mock）
```

判定逻辑：启动时读 config.json + `safeValidateConfig` + DeepSeek Key 检查；config 变化时（用户配置后）实时重判 ready/needs。

联动：
- `InputView`：非 `ready` 时首页显示缺配置引导卡，`ready` 才显示输入类型标签。
- `ConfigWizard`：`initialStep` 缺项直达（缺 Key→keys、缺输出→output）。
- `usePipeline.submit`：非 `ready` 拦截 + 提示（浏览器 mock 放行）。
- `SettingsView`：非首启 `needs_config` 自动开一次向导（直达缺项步）。

`firstLaunch` 保留（首启自动开向导），就绪判定统一用 `setupStatus`。

## 九、设置页结构（SettingsPage）

左-右双栏：左侧导航 Tab，右侧内容。Tab：

| Tab | 内容 |
|-----|------|
| 概览 | 外观主题、快捷操作（重新检测依赖/打开向导/重置配置/测试 AI 连接） |
| API 密钥 | AI 模型选择 + DeepSeek Key + AI Douyin Key |
| 处理能力 | 本机依赖 + 语音识别（faster-whisper）+ 视频解析 |
| 输出 | 笔记输出目录 + 文件管理（清理临时文件/打开缓存目录）+ 元信息 |
| 笔记内容 | Mermaid/扩展资源/评论区/关键帧（含 AI 截图审查）/教程检测/阅读信息 |
| 高级 | Python 路径 + ASR 高级参数（compute_type）+ 收尾操作 |
| 关于 | 应用信息/技术栈/开源协议/免责声明 |

健康度卡片：DeepSeek / Python / FFmpeg / 输出目录 四项状态（正常/警告/阻塞/未配置）。
