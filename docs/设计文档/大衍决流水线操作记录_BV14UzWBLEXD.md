## 六、App 化建议

基于本次测试发现的问题，建议在 App 化时重点解决：

### 1. 路径统一
- App 内所有文件操作使用同一个临时目录
- 不要依赖 Claude Write 工具写入 Bash 可访问的路径
- 建议：App 自己管理临时目录，通过绝对路径传递

### 2. Python 调用统一
- 检测 `python3` / `python` / `py` 哪个可用
- 或配置 `FW_PYTHON` 为必填项

### 3. 截图链路重构
- 字幕分析（步骤 4.5）→ 截图（步骤 4.7）→ 审查（步骤 7.1）需要端到端打通
- App 环境可以直接渲染 PNG，不需要依赖外部 Read 工具
- 场景检测阈值需针对代码/IDE 画面调优

### 4. 元信息获取前置
- 在灵力预估之前先获取视频元信息（时长是估算的关键参数）
- AI Douyin API 若不返回元信息 → 自动 fallback 到 yt-dlp 或 B 站 API

### 5. 评论区独立
- B 站评论区需要 `aid`（av 号），需从 B 站页面 API 或 yt-dlp 获取
- 可作为独立步骤异步执行

### 提示词设计的断点

| 问题 | 说明 |
| --- | --- |
| **步骤 5 和 7 提示词高度重叠** | 两者都要求读字幕全文 → 生成总结 → 输出结构化内容。实际执行中被合并，步骤 5 的输出（摘要+要点）被步骤 7 覆盖 |

| **提示词依赖 Claude 视觉能力** | 截图审查、教程检测等功能假设模型能"看"图片并理解代码/PPT/人脸的区别，App 化后需要替换为计算机视觉方案 |
