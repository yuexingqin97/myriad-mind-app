# 输出目录知识库索引设计

> 目标：在用户指定的笔记输出目录下创建 `.myriad-mind/`，记录当前目录内所有文档的轻量索引，作为 AI 生成前的目录记忆、分类依据、重复炼化判断依据，并为后续修为面板做数据准备。

---

## 一、设计结论

每个输出目录都是一个独立知识库。

```text
用户选择的输出目录/
├── Rust/
│   └── Rust异步编程.md
├── AI/
│   └── DeepSeek长上下文实践.md
├── Tauri/
│   └── Tauri打包发布流程.md
└── .myriad-mind/
    ├── library.json
    ├── notes.jsonl
    ├── categories.json
    ├── fingerprints.json
    ├── memory.md
    └── scan-state.json
```

`.myriad-mind/` 是目录级索引，不是单篇笔记元信息。

两者职责不同：

| 层级 | 文件 | 职责 |
|------|------|------|
| 单篇笔记 | `.md` 文件末尾 `## 大衍决心得` | 单篇笔记的来源、版本、模型、标签、fingerprint |
| 输出目录 | `.myriad-mind/` | 整个知识库的分类、去重、检索、AI 记忆、修为面板基础数据 |

`.myriad-mind/` 可以随时重建：如果用户删除它，App 扫描所有 Markdown，根据每篇文档末尾元信息重建索引。

---

## 二、核心用途

### 2.1 生成前让 AI 互相参考

AI 生成新文档前，不只看当前输入，还要看当前输出目录的已有知识结构：

```text
已有分类
已有笔记标题
已有摘要
已有标签
已有来源 fingerprint
相似笔记候选
```

这样可以让 AI 避免重复造一篇相似文档，也能延续用户已有知识体系。

### 2.2 自动分类与落盘位置

新的炼化请求进入后，App 先决定：

```text
应该放在哪个一级目录？
应该新建哪个文件？
是否命中已有文件？
是否做增量更新？
```

例如用户输出目录已有：

```text
Rust/
Tauri/
AI/
```

新输入被识别为 Rust async 内容时，优先落到：

```text
Rust/Rust异步编程.md
```

如果同一输入已存在，则更新原文件，而不是新建。

### 2.3 为修为面板准备

修为面板不需要每次从零扫描全目录。

它可以直接读取 `.myriad-mind/notes.jsonl` 和 `categories.json`：

- 笔记总数。
- 分类分布。
- 标签云。
- 难度分布。
- 最近学习。
- 来源类型。
- 模型使用统计。
- 更新次数。

## 三、目录文件设计

### 3.1 `library.json`

知识库自身信息。

```json
{
  "schema": "myriad-mind-library/v1",
  "library_id": "lib_8f31a2c9",
  "root": "D:/Notes/MyriadMind",
  "created_at": "2026-05-31T22:00:00+08:00",
  "updated_at": "2026-05-31T23:10:00+08:00",
  "app": {
    "name": "myriad-mind-app",
    "version": "0.1.0-alpha.1",
    "build": "20260531.1"
  },
  "index": {
    "note_count": 42,
    "category_count": 8,
    "last_scan_at": "2026-05-31T23:10:00+08:00",
    "last_full_rebuild_at": "2026-05-31T22:00:00+08:00"
  }
}
```

### 3.2 `notes.jsonl`

一行一篇笔记，便于追加和增量维护。

```jsonl
{"id":"note_9f3a2c1b","path":"Rust/Rust异步编程.md","title":"Rust 异步编程","category":"Rust","summary":"解释 Rust async/Future 的核心机制。","tags":["Rust","异步编程","Future"],"topics":["Rust","async","Future"],"difficulty":"intermediate","current_version":2,"updated_at":"2026-05-31T22:45:08+08:00","sources":["sha256:abc123"],"ai_model":"deepseek-v4-pro"}
{"id":"note_2b7cd912","path":"Tauri/Tauri打包发布流程.md","title":"Tauri 打包发布流程","category":"Tauri","summary":"记录 Tauri Windows 发布和 FFmpeg 打包流程。","tags":["Tauri","发布","FFmpeg"],"topics":["Tauri","Release"],"difficulty":"intermediate","current_version":1,"updated_at":"2026-05-31T21:10:00+08:00","sources":["sha256:def456"],"ai_model":"deepseek-v4-pro"}
```

### 3.3 `categories.json`

分类目录和别名。

```json
{
  "schema": "myriad-mind-categories/v1",
  "categories": [
    {
      "name": "Rust",
      "path": "Rust",
      "aliases": ["rust", "Rust语言", "Rust 编程"],
      "note_count": 12,
      "tags": ["Rust", "async", "trait", "生命周期"]
    },
    {
      "name": "AI",
      "path": "AI",
      "aliases": ["人工智能", "LLM", "DeepSeek", "大模型"],
      "note_count": 9,
      "tags": ["DeepSeek", "Prompt", "长上下文"]
    }
  ]
}
```

### 3.4 `fingerprints.json`

输入来源去重索引。

```json
{
  "schema": "myriad-mind-fingerprints/v1",
  "items": {
    "sha256:abc123": {
      "note_id": "note_9f3a2c1b",
      "path": "Rust/Rust异步编程.md",
      "source_raw": "https://www.bilibili.com/video/BVxxx",
      "source_type": "bilibili",
      "first_seen_at": "2026-05-31T21:30:12+08:00",
      "last_used_at": "2026-05-31T22:45:08+08:00"
    }
  }
}
```

### 3.5 `memory.md`

给 AI 使用的轻量目录记忆。

它不是给用户阅读的正式笔记，而是给 DeepSeek 分类和生成前参考。

```markdown
# 大衍决知识库记忆

> 自动生成。用于帮助 AI 了解当前输出目录已有笔记、分类和主题，避免重复生成。

## 分类概览

- Rust：12 篇，主题包括 async、trait、生命周期、Bevy。
- AI：9 篇，主题包括 DeepSeek、Prompt、长上下文。
- Tauri：5 篇，主题包括打包、插件、资源内置。

## 最近笔记

| 标题 | 分类 | 摘要 | 路径 |
|------|------|------|------|
| Rust 异步编程 | Rust | 解释 async/Future 核心机制 | Rust/Rust异步编程.md |
| Tauri 打包发布流程 | Tauri | Windows 发布和 FFmpeg 内置 | Tauri/Tauri打包发布流程.md |

## 分类建议

- Rust 相关内容优先放入 `Rust/`。
- DeepSeek、Prompt、模型调用放入 `AI/`。
- Tauri、桌面端、打包发布放入 `Tauri/`。
```

### 3.6 `scan-state.json`

扫描状态，用来判断是否需要重建索引。

```json
{
  "last_scan_at": "2026-05-31T23:10:00+08:00",
  "files": {
    "Rust/Rust异步编程.md": {
      "mtime": "2026-05-31T22:45:08+08:00",
      "size": 32891,
      "hash": "sha256:filehash"
    }
  }
}
```

## 四、AI 输出文档前必须做的事情

新增“落盘规划”阶段，发生在真正调用 `note_generation` 之前。

```text
用户输入
→ 输入识别
→ 确保输出目录和 .myriad-mind 存在
→ 扫描 / 刷新目录索引
→ 计算 source_fingerprint
→ 生成候选分类和候选文件
→ 判断新建 / 更新 / 增量
→ 用户确认或自动执行
→ 调用 AI 生成文档
→ 写入 Markdown
→ 更新 .myriad-mind 索引
```

### 4.1 确保索引目录存在

如果用户配置的输出目录是：

```text
D:/Notes/MyriadMind
```

启动炼化前确保：

```text
D:/Notes/MyriadMind/.myriad-mind/
```

存在。

如果不存在：

1. 创建 `.myriad-mind/`。
2. 扫描输出目录现有 `.md`。
3. 读取每篇文末“大衍决心得”。
4. 缺失则规则补全，必要时进入元信息修复队列。
5. 写出 `library.json`、`notes.jsonl`、`categories.json`、`fingerprints.json`。
6. 生成一个简略版 `memory.md`。

首次生成 `.myriad-mind/` 时要轻量，不能为了建索引就把所有文档全文塞给 AI。

推荐策略：

| 场景 | 行为 |
|------|------|
| 文档有大衍决心得 | 直接读取 title / category / summary / tags / sources |
| 文档无元信息 | 规则读取 H1、父目录、文件名、前 1000 字 |
| 文档很多 | 只抽取每篇 1 行摘要，不调用 AI 全量总结 |
| 文档特别长 | 只取标题、目录、前 1000 字、末尾更新记录 |
| 分类不确定 | 先放入 `未分类`，后续后台整理 |

首次 `memory.md` 只需要能帮助下一次炼化做粗分类：

```markdown
# 大衍决知识库记忆

> 自动生成的简略索引。用于帮助 AI 判断分类和避免重复生成。

## 分类概览

- Rust：8 篇
- AI：3 篇
- 未分类：5 篇

## 笔记索引

| 标题 | 分类 | 路径 |
|------|------|------|
| Rust 异步编程 | Rust | Rust/Rust异步编程.md |
| Tauri 打包发布流程 | Tauri | Tauri/Tauri打包发布流程.md |
```

### 4.2 生成分类

分类优先级：

```text
1. 用户在炼化按钮旁指定的子目录
2. source_fingerprint 命中已有笔记
3. .myriad-mind/categories.json 现有目录和别名匹配
4. DeepSeek 根据输入标题、摘要、目录记忆生成分类建议
5. 低置信度时放入 未分类
```

### 4.3 判断是否命中同一个文件

命中规则：

| 命中类型 | 条件 | 行为 |
|----------|------|------|
| 精确命中 | `source_fingerprint` 已存在 | 更新对应文件 |
| 用户指定命中 | 用户选择已有文件 | 增量更新该文件 |
| 高相似命中 | 标题 / 摘要 / 标签与已有笔记高度相似 | 提示用户确认 |
| 分类命中 | 只命中分类目录 | 在该目录新建文件 |
| 无命中 | 没有分类和相似笔记 | 新建分类或放入未分类 |

默认不要自动把不同输入合并到同一个文件，除非：

- 用户明确指定。
- source_fingerprint 相同。
- AI 高置信判断且用户确认。

## 六、AI 如何使用目录记忆

生成文档前，MindEngine 需要拿到一个压缩版知识库上下文：

```text
当前输出目录：D:/Notes/MyriadMind
已有分类：Rust, AI, Tauri
本次推荐分类：Rust
目标文件：Rust/Rust异步编程.md
命中原因：source_fingerprint 相同，属于重新炼化
相似笔记：
1. Rust 异步编程：解释 async/Future...
2. Bevy ECS 系统调度：涉及 Rust ECS...

生成要求：
- 如果是 update_note：更新当前文档，并追加 vN 更新记录。
- 如果是 append_to_note：保留原正文，追加增量记录，必要时重写摘要。
- 如果是 create_note：按目标分类新建文档。
```

注意：

- 不要把整个知识库都塞给 AI。
- P0 只给分类概览 + 相似笔记 Top 5 + 目标文件摘要。
- 真正需要合并已有文件时，才读取目标文件全文。
- `memory.md` 只是目录记忆的压缩视图，不是越长越好。

## 6.1 记忆容量与遗忘策略

`.myriad-mind` 的记忆要服务“生成前决策”，不是保存所有历史细节。

### 6.1.1 推荐容量

| 文件 | 建议上限 | 超过后处理 |
|------|----------|------------|
| `memory.md` | 20KB - 50KB | 压缩旧内容，只保留分类摘要和最近/重要笔记 |
| `notes.jsonl` | 可较大 | 保留全量轻索引，每行仍保持短小 |
| `categories.json` | 可较小 | 合并低频别名和过期标签 |
| `fingerprints.json` | 可较大 | 可长期保留，用于去重 |

### 6.1.2 `memory.md` 内容优先级

保留：

1. 分类概览。
2. 每个分类最重要 / 最近的 5-10 篇笔记。
3. 最近 20 篇更新过的笔记。
4. 用户手动指定为重要的笔记。
5. 常见分类别名和放置规则。

可以遗忘：

1. 很久没更新、没追问、没被引用的低频笔记摘要。
2. 重复标签。
3. 太细的章节摘要。
4. 旧模型运行细节。
5. 已经在单篇 Markdown 元信息里存在、但对分类无帮助的字段。

### 6.1.3 遗忘不是删除笔记

遗忘只影响 `.myriad-mind/memory.md` 的压缩视图。

不会删除：

- 用户 Markdown 笔记。
- 单篇文末“大衍决心得”。
- `notes.jsonl` 基础索引。
- `fingerprints.json` 去重记录。

如果未来需要完整信息，可以从 Markdown 重新扫描。

### 6.1.4 触发压缩

以下情况触发 memory 压缩：

- `memory.md` 超过大小阈值。
- 笔记数量超过阈值，例如 200 篇。
- 用户点击“整理知识库索引”。
- App 升级导致索引 schema 变化。
- 一次批量导入后。

压缩方式：

```text
读取 notes.jsonl
→ 按 category 聚合
→ 每类保留 Top N
→ 最近更新单独保留
→ 写回 memory.md
```

P0 用规则压缩即可；P1 再让 DeepSeek Flash 生成更自然的分类记忆。

## 七、索引更新时机

### 7.1 新建笔记后

写入：

- 新 Markdown 文件。
- 文末“大衍决心得”。
- `notes.jsonl` 新记录。
- `categories.json` 分类计数。
- `fingerprints.json` 新 fingerprint。
- `memory.md` 追加或刷新一条简短摘要。

新建笔记时可以比首次扫描多存一点记忆信息，因为此时刚刚生成内容，摘要、标签、分类、来源、模型都已经在上下文里：

```json
{
  "title": "Rust 异步编程",
  "category": "Rust",
  "summary": "解释 Rust async/Future 的核心机制。",
  "tags": ["Rust", "异步编程", "Future"],
  "importance": 0.72,
  "updated_at": "2026-05-31T22:45:08+08:00"
}
```

但不要存完整正文，也不要存完整 ASR。

### 7.2 更新已有笔记后

更新：

- Markdown 文末元信息：`current_version + 1`。
- `notes.jsonl` 对应记录。
- `fingerprints.json.last_used_at`。
- `memory.md` 对应摘要。

更新已有笔记时：

- 如果只是同一输入重新炼化，刷新该笔记摘要、标签、版本号。
- 如果是不同输入增量合并，追加来源 fingerprint，并更新摘要。
- 如果笔记变得过长，只在 `memory.md` 保留“这篇笔记现在覆盖哪些主题”，不记录全部新增内容。

### 7.3 用户手动修改文件后

下一次启动或炼化前：

1. 读取 `scan-state.json`。
2. 对比 mtime / size。
3. 有变化则重新解析该 `.md`。
4. 如果元信息缺失，走元信息自动修复。
5. 更新索引。

## 八、与 Markdown 元信息的关系

`.myriad-mind/` 是索引缓存，Markdown 末尾元信息是事实来源。

原则：

```text
Markdown 元信息 > .myriad-mind 索引
```

如果两者冲突：

1. 以 Markdown 末尾元信息为准。
2. 重建 `.myriad-mind` 对应记录。
3. 如果 Markdown 元信息缺失，再用 `.myriad-mind` 作为修复线索。

这样用户复制单篇 Markdown 时不会丢核心信息；用户复制整个输出目录时则保留完整知识库索引。

## 十、隐私与安全

`.myriad-mind/` 不存：

- API Key。
- Cookie。
- 用户密钥。
- 完整原始视频。
- 完整 ASR 文本。

可以存：

- 文档标题。
- 相对路径。
- 摘要。
- 标签。
- 来源 URL。
- fingerprint。
- 模型名。
- App 版本。

如果用户不希望索引暴露来源 URL，可以在设置中增加：

```text
[ ] 在目录索引中保存原始 URL
```

关闭后：

- 单篇 Markdown 仍可按用户设置保存来源。
- `.myriad-mind/fingerprints.json` 只存 fingerprint，不存 raw URL。

## 十二、P0 / P1 切分

### P0

- 创建 `.myriad-mind/`。
- 扫描 Markdown，读取末尾元信息。
- 生成 `notes.jsonl`、`categories.json`、`fingerprints.json`。
- 缺少 `.myriad-mind/` 时自动生成简略 `memory.md`。
- `memory.md` 超过阈值时用规则压缩。
- 根据 fingerprint 判断重复炼化。
- 根据已有一级目录做自动分类。
- 命中同一输入时更新已有文件。
- 写完笔记后更新索引。

### P1

- DeepSeek Flash 优化 `memory.md` 摘要。
- DeepSeek Flash 参与分类和相似笔记判断。
- UI 展示命中已有文件提示。
- 支持用户选择已有笔记做增量更新。
- 支持“整理知识库索引”按钮。

### P2

- 修为面板直接读取 `.myriad-mind`。
- 批量整理元信息。
- 跨目录知识库合并。
- 相似主题自动建议合并。

## 十三、验收标准

- 用户选择输出目录后，App 自动创建 `.myriad-mind/`。
- `.myriad-mind/` 内至少生成 `library.json`、`notes.jsonl`、`categories.json`、`fingerprints.json`。
- 新炼化前会先生成 `PlacementPlan`。
- 如果 `source_fingerprint` 命中已有笔记，默认更新该笔记而不是新建。
- 如果只命中已有分类目录，则在该分类下新建文件。
- 用户可以在炼化按钮旁手动指定子目录或已有笔记。
- 写入新文档或更新文档后，`.myriad-mind` 索引同步更新。
- 删除 `.myriad-mind/` 后，App 可以通过扫描 Markdown 重建索引。
- 缺少 `.myriad-mind/` 时，首次生成的 `memory.md` 是简略索引，不读取全文。
- 新建或更新文档后，`memory.md` 会增量更新少量摘要。
- `memory.md` 超过阈值时可以压缩或遗忘低价值摘要。
- 修为面板后续可以直接消费 `.myriad-mind/notes.jsonl`。
