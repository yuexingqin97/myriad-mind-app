# 修为界面与设置界面设计方案

> 本文只描述设计，不涉及代码实现。目标是先确定信息架构、布局、状态和交互，再进入实现。

## 一、整体产品结构

桌面端主导航建议保持三大页：

```text
炼化    修为    设置
```

- 炼化：输入与 AI 输出工作台。
- 修为：学习成果、笔记资产、成长进度。
- 设置：让应用能稳定运行的配置中心。

三页的职责要清晰分开：

- 炼化页回答：“我现在要处理什么？”
- 修为页回答：“我已经积累了什么？”
- 设置页回答：“系统是否配置好了？”

# 二、修为界面设计

## 2.1 页面定位

修为界面不是单纯统计页，而是用户的“学习成果中心”。

它应该展示：

1. 当前学习等级。
2. 已生成的笔记资产。
3. 最近学习轨迹。
4. 标签、主题、技术栈分布。
5. 成就与连续学习反馈。

## 2.2 核心体验目标

用户进入修为页后，应能立刻知道：

- 我现在处于什么阶段？
- 我最近学了什么？
- 我的知识积累在哪些方向？
- 哪些笔记可以继续打开？
- 下一步推荐学习什么？

## 2.3 推荐布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 修为面板                                      刷新统计  打开目录 │
│ 修炼进度、笔记资产、知识结构和学习连续性                       │
├──────────────────────────────────────────────────────────────┤
│ 当前境界卡片                                                   │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 炼气中期 · 126 修为点                                     │ │
│ │ ███████████░░░░░░░  62%                                  │ │
│ │ 距离筑基还差 74 点                                        │ │
│ └──────────────────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────┤
│ 数据概览                                                       │
│ ┌───────┬───────┬───────┬───────┬───────┐                  │
│ │ 笔记数 │ 学习时长│ 来源数 │ 技术栈 │ 连续天数│                  │
│ └───────┴───────┴───────┴───────┴───────┘                  │
├───────────────────────────────┬──────────────────────────────┤
│ 最近笔记                       │ 知识分布                     │
│ - Rust 异步编程                 │ #Rust      12                │
│ - Bevy ECS 架构                 │ #AI         8                │
│ - DeepSeek 长上下文实践          │ #Tauri      5                │
├───────────────────────────────┴──────────────────────────────┤
│ 成就 / 下一步建议                                              │
└──────────────────────────────────────────────────────────────┘
```

## 2.4 页面模块

### A. 顶部概览区

内容：

- 标题：修为面板。
- 副标题：修炼进度、统计面板、笔记资产。
- 操作按钮：
  - 刷新统计
  - 打开笔记目录
  - 导出修为面板

设计建议：

- 不做大横幅。
- 标题区紧凑，给数据内容留空间。

### B. 当前境界卡片

这是修为页的主视觉。

展示字段：

- 当前境界：如 `炼气中期`
- 修为点：如 `126`
- 进度条：当前等级进度
- 下一境界：如 `筑基`
- 差距说明：如 `距离筑基还差 74 点`

推荐样式：

```text
当前境界：炼气中期
126 修为点

炼气中期 ━━━━━━━━━━━━━━━ 62% ───── 筑基

距离筑基还差 74 点
```

状态增强：

- 如果今日新增笔记，显示 `今日 +12 修为点`。
- 如果连续学习中，显示 `连续学习 3 天`。

### C. 数据概览卡片

建议横向 5 个统计卡片，桌面端一行展示。

字段：

- 笔记总数
- 学习时长
- 知识来源
- 技术栈数量
- 连续学习天数

次级字段可放到详细区：

- 入门笔记
- 进阶笔记
- 深入笔记
- 平均阅读时长

原则：

- 首页只放核心数据。
- 不要把 8 个统计卡片全部平铺到第一屏，否则显得像后台报表。

### D. 最近笔记

这是修为页最实用的模块。

每条笔记展示：

- 类型图标：视频 / 文章 / 音频 / 代码
- 标题
- 日期
- 难度
- 阅读时长
- 标签

交互：

- 点击笔记：用系统默认编辑器打开 `.md`。
- 右侧更多按钮：
  - 打开文件
  - 打开所在目录
  - 复制 Markdown

空状态：

```text
还没有笔记
去炼化页粘贴一个链接，生成的学习笔记会出现在这里。
```

### E. 知识分布

用于展示用户学过哪些方向。

第一版建议做“标签排行榜”，不要急着上复杂知识图谱。

展示：

```text
#Rust        12
#AI           8
#Tauri        5
#Bevy         4
#Prompt       3
```

后续可以扩展：

- 标签关系图
- 技术栈雷达图
- 按来源分类
- 按难度分类

### F. 成就区

成就不要占太大面积，建议放在页面下半部分。

每个成就：

- 图标
- 名称
- 解锁状态
- 简短说明

展示策略：

- 已解锁在前。
- 未解锁降低透明度。
- 每行 3-4 个。

### G. 下一步建议

这是可以体现 AI 产品感的区域。

示例：

```text
下一步建议

你最近集中学习了 Rust 和 Tauri，可以继续补：
1. Tauri 文件系统权限模型
2. Rust async runtime 基础
3. 桌面端打包与自动更新
```

第一版可以先静态规则生成：

- 根据 topTags 推荐。
- 根据最近笔记类型推荐。
- 根据薄弱分类推荐。

## 2.5 修为页状态

### 空状态

当没有笔记：

- 显示一个轻量空状态。
- 提供“去炼化”按钮。
- 不显示大量 0 数据卡片。

### 有数据状态

展示完整面板。

### 扫描中状态

显示：

- 正在扫描笔记目录。
- 已扫描文件数。
- 当前目录。

### 错误状态

常见错误：

- 输出目录不存在。
- 没有权限读取。
- 笔记格式解析失败。

提示要可行动：

- 重新选择目录
- 打开设置
- 重新扫描

## 2.6 修为页验收标准

- 第一屏能看到当前境界、核心统计、最近笔记。
- 无笔记时有清晰空状态。
- 最近笔记可以打开。
- 统计刷新不会阻塞页面。
- 输出目录异常时能引导用户去设置。

# 三、设置界面设计

## 3.1 页面定位

设置页不是“所有字段的大表单”，而是“系统可用性中心”。

它需要优先回答：

- 我还能不能正常炼化？
- 哪些能力已经配置？
- 哪些配置会影响视频、文章、AI 生成？
- 高级参数在哪里调？

## 3.2 设置页结构

建议从当前横向 Tab 改为两层结构：

```text
设置
├── 快速配置
│   ├── 系统依赖
│   ├── API 密钥
│   ├── 输出目录
│   └── 处理方案
└── 高级设置
    ├── AI 模型
    ├── 语音识别
    ├── 视频解析
    ├── 笔记内容
    ├── 文件管理
    └── 关于
```

如果继续使用 Tab，建议 Tab 调整为：

```text
概览    API 密钥    处理能力    输出    笔记内容    高级    关于
```

## 3.3 推荐布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 设置                                                         │
│ 管理应用配置、API 密钥和本机处理能力                         │
├──────────────────────────────────────────────────────────────┤
│ 配置健康度                                                   │
│ ┌─────────────┬─────────────┬─────────────┬─────────────┐   │
│ │ DeepSeek ✅  │ Python ✅    │ FFmpeg ⚠️   │ 输出目录 ✅  │   │
│ └─────────────┴─────────────┴─────────────┴─────────────┘   │
│ 当前状态：文章处理可用，视频处理缺少 FFmpeg                  │
├──────────────────────────────────────────────────────────────┤
│ 左侧设置导航                 │ 右侧设置内容                  │
│                              │                               │
│ 概览                         │ 系统依赖                       │
│ API 密钥                     │ Python                         │
│ 处理能力                     │ FFmpeg                         │
│ 输出                         │ yt-dlp                         │
│ 笔记内容                     │ GPU                            │
│ 高级                         │                               │
│ 关于                         │                               │
└──────────────────────────────────────────────────────────────┘
```

## 3.4 顶部健康度区域

设置页第一屏应该先显示健康度。

四个核心状态：

- DeepSeek API Key
- Python
- FFmpeg / yt-dlp
- 输出目录

状态分类：

| 状态 | 展示 | 含义 |
|------|------|------|
| 正常 | 绿色 | 能使用 |
| 警告 | 黄色 | 可降级使用 |
| 阻塞 | 红色 | 核心功能不可用 |
| 未配置 | 灰色 | 可稍后配置 |

示例文案：

```text
当前状态：文章处理可用，视频处理缺少 FFmpeg。
```

或：

```text
当前状态：还缺 DeepSeek API Key，暂时无法生成笔记。
```

## 3.5 设置导航

### 概览

展示：

- 配置健康度
- 当前配置路径
- 输出目录
- 最近检测时间
- 快捷操作：
  - 重新检测
  - 打开配置向导
  - 重置配置

### API 密钥

展示：

- DeepSeek API Key，必填。
- AI Douyin API Key，可选。
- TikHub Token，可选。
- 火山引擎 Token，可选。

交互：

- 已配置只显示脱敏。
- 编辑时显示密码输入框。
- 保存后立即写入 OS 密钥链。
- 不在页面上显示完整密钥。

重点提示：

```text
密钥只保存在系统凭据管理器，不写入配置文件。
```

### 处理能力

整合原来的 ASR、视频解析、系统依赖。

分组：

1. 本机依赖
   - Python
   - FFmpeg
   - yt-dlp
   - GPU / CUDA

2. 语音识别
   - faster-whisper
   - 火山引擎

3. 视频解析
   - AI Douyin
   - TikHub
   - YouTube yt-dlp

这样用户能理解：这些配置都属于“处理输入内容”的能力。

### 输出

展示：

- 笔记输出目录
- 临时文件清理
- 元信息写入
- 调试元信息

推荐增加操作：

- 选择目录
- 打开目录
- 测试写入

### 笔记内容

展示功能开关：

- 关键帧截图
- Mermaid 图表
- 扩展学习资源
- 评论区精华
- 阅读时长与难度
- 灵力预估

关键帧高级项放在同组下方：

- 截图间隔
- 最大截图数
- 截图模式

### 高级

放低频配置：

- 模型大小
- compute type
- 自定义 Python 路径
- 调试模式
- 配置 JSON 路径
- 清空本地缓存

高级区要避免影响新手。

### 关于

展示：

- 应用名称
- 版本
- 技术栈
- 许可证
- 免责声明

## 3.6 设置页交互原则

### 保存策略

建议保留底部 sticky 保存栏。

但 API Key 是即时保存，因为它写入密钥链。

普通配置：

- 用户修改后显示 `有未保存修改`。
- 点击保存后写入 `config.json`。
- 保存成功显示 `已保存`。

### 检测策略

依赖检测不应该只在进入页面时做一次。

需要：

- 进入设置页自动检测。
- 点击“重新检测”手动检测。
- 修改 Python 路径后自动重新检测。

### 阻塞提示

当缺少关键配置时，要明确影响范围。

示例：

```text
缺少 DeepSeek API Key
影响：无法生成 AI 笔记
处理：配置 DeepSeek API Key
```

```text
缺少 FFmpeg
影响：本地视频和部分在线视频无法提取音频
处理：安装 FFmpeg 或仅处理文章内容
```

## 3.7 设置页状态

### 全部就绪

```text
全部核心能力已就绪，可以处理文章、视频和本地文件。
```

### 部分可用

```text
文章处理可用；视频处理缺少 FFmpeg。
```

### 核心阻塞

```text
还缺 DeepSeek API Key，暂时无法生成笔记。
```

### 开发模式

浏览器预览时：

```text
当前为浏览器预览模式，密钥链与系统依赖检测使用模拟结果。
```

## 3.8 设置页验收标准

- 用户进入设置页第一眼能看到系统是否可用。
- API Key 不会明文显示。
- 修改普通配置后需要保存。
- 修改 Python 路径后依赖状态会更新。
- 输出目录可以清楚看到。
- 新用户可以通过“打开配置向导”完成最小配置。
- 高级选项不会干扰首次使用。

# 四、视觉规范建议

## 4.1 色彩

当前暗色基调可以保留，但建议明确语义色：

- 主色：紫蓝，用于主按钮、选中状态、当前进度。
- 成功：绿色，用于已配置、已完成。
- 警告：黄色，用于可降级。
- 错误：红色，用于阻塞。
- 中性：灰色，用于未配置、说明文案。

## 4.2 卡片

建议：

- 普通卡片圆角 8px。
- 重要卡片可以 10px。
- 避免大面积嵌套卡片。
- 设置页不要每个字段都包一层卡片，分组即可。

## 4.3 字体层级

建议：

- 页面标题：22px
- 区块标题：14px
- 正文：13px
- 辅助说明：11-12px
- 数据数字：20-28px

## 4.4 密度

这是桌面工具，不需要太营销化。

建议：

- 修为页偏数据仪表盘，密度中等。
- 设置页偏工具配置，密度略高。
- 避免大段说明文字。

# 五、实现优先级

## P0

- 修为页：当前境界、核心统计、最近笔记。
- 设置页：健康度、API 密钥、依赖检测、输出目录。

## P1

- 修为页：标签分布、成就区、空状态。
- 设置页：处理能力整合、笔记内容开关。

## P2

- 修为页：下一步建议、知识图谱。
- 设置页：配置导入导出、重置配置、高级调试。

---

# 六、最终建议

修为页要做成“成果感”，让用户看到自己已经积累了东西。

设置页要做成“可用性检查中心”，让用户知道哪里缺、缺了影响什么、该怎么补。

两者都不要变成普通表单页。修为页给反馈，设置页给确定性。
