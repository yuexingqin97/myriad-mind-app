# 开发启动指南

> 最后更新：2026-06-14
>
> 本文档讲清楚：如何从零启动大衍决桌面端、每个 npm/pnpm 脚本干啥、踩哪些坑。

---

## 一、前置环境

| 依赖 | 版本 | 用途 | 安装 |
|------|------|------|------|
| Node.js | 24+ | 前端构建 | https://nodejs.org/ |
| Rust | 1.93+ | 桌面后端 | https://rustup.rs/ |
| Python | 3.9+（开发机 3.12）| 视频处理脚本 | https://www.python.org/ |
| FFmpeg | 8.x | 音频提取/关键帧 | https://ffmpeg.org/ |
| yt-dlp | 最新 | 视频下载/字幕 | `pip install yt-dlp` |
| pnpm | 9+（项目锁定 11.5.0）| 包管理 | 见下文 |

GPU（CUDA）可选，用于 faster-whisper 加速 ASR；没有则 CPU 跑。

---

## 二、⚠️ 必须用 pnpm，不是 npm

这是 **pnpm workspace monorepo**，`packages/*` 之间用 `workspace:*` 协议互相引用。**npm 不认这个协议**，直接 `npm install` / `npm run dev` 会报错。

一次性启用 pnpm（推荐用 corepack 自动锁定版本）：

```bash
corepack enable
```

项目根 `package.json` 已声明 `packageManager: pnpm@11.5.0`，corepack 会自动用这个版本。

## 三、首次启动（从零开始）

```bash
# 1. 克隆（已有则跳过）
git clone <repo-url>
cd myriad-mind-app

# 2. 安装所有依赖（root + workspace 包）
pnpm install

# 3. 构建两个 workspace 共享包（desktop 引用的是它们的 dist/，不是 src/）
pnpm build:core && pnpm build:ui

# 4. 启动桌面端（Vite 前端 :1420 + Tauri Rust 后端，热重载）
pnpm dev
```

> 首次会编译 Rust（几分钟），之后增量编译很快。首启弹出配置向导：填 Python 路径 → 安装 faster-whisper → 填 DeepSeek API Key（存 OS 密钥链）。

## 四、日常开发（依赖已装、dist 已构建）

```bash
pnpm dev          # 一条命令启动桌面端
```

### 脚本对照表

#### 根目录 `package.json`

| 命令 | 作用 |
|------|------|
| `pnpm dev` | 启动桌面端（= `pnpm dev:desktop` = `tauri dev`）|
| `pnpm dev:desktop` | 同上，显式 |
| `pnpm dev:desktop:web` | 只跑前端 Vite（浏览器 `:1420`，不起 Rust，Tauri API 降级）|
| `pnpm dev:mobile` | 移动端（v2 延后，当前不用）|
| `pnpm build` | 构建 core + ui + desktop |
| `pnpm build:core` | 仅构建 `@myriad-mind/core`（出 `packages/core/dist/`）|
| `pnpm build:ui` | 仅构建 `@myriad-mind/ui`（出 `packages/ui/dist/`）|
| `pnpm build:desktop` | 仅构建桌面前端（`tsc && vite build`）|
| `pnpm typecheck` | 全 workspace 类型检查 |
| `pnpm lint` | 占位（暂无 lint 配置）|
| `pnpm clean` | 清理 dist/build/target/.expo/node_modules |

#### `apps/desktop/package.json`（在 apps/desktop 目录下用）

| 命令 | 作用 | 是桌面版？ |
|------|------|-----------|
| `pnpm dev` | 只跑 Vite → 浏览器 `:1420` | ❌ 纯前端，无 Rust |
| `pnpm dev:desktop` | `tauri dev`，编译 Rust + 拉起 vite → 桌面窗口 | ✅ **启动桌面版** |
| `pnpm build` | 前端构建（`tsc && vite build`）| — |
| `pnpm build:desktop` | `tauri build`，打包 Windows 安装包 | ✅ 打包桌面版 |
| `pnpm preview` | 预览前端构建产物 | — |
| `pnpm typecheck` | TS 类型检查 | — |

**记忆口诀：带 `:desktop` 后缀的才是桌面版（叠了 Tauri），不带的是纯前端。**

## 五、`pnpm dev` 调用链（看懂就不会被两层 `pnpm dev` 迷惑）

```
根目录 pnpm dev
  └─ pnpm -F @myriad-mind/desktop tauri dev          （根 package.json: dev:desktop）
     └─ tauri.conf.json: beforeDevCommand = "pnpm dev"
        └─ apps/desktop 下再跑 pnpm dev = vite        （desktop package.json: dev）
           └─ Vite 在 :1420 起前端 dev server
     └─ Tauri 编译 Rust 并启动窗口，指向 localhost:1420
```

两层 `pnpm dev` 是**正常的嵌套**：外层是根的桌面启动命令，内层是 Tauri 钩子自动拉起的 vite 子步骤。

## 六、纯前端调试（不起 Rust）

只想快速看 UI、改样式时用，不等 Rust 编译：

```bash
pnpm dev:desktop:web
# 浏览器访问 http://localhost:1420
```

⚠️ 浏览器里 Tauri API（`invoke`、文件系统、密钥链）不可用，`api.ts` 的浏览器降级会生效——能看 UI，但炼化/配置等依赖后端的功能跑不了。

## 七、打包 Windows 安装包

```bash
pnpm build:desktop
# 或：pnpm -F @myriad-mind/desktop tauri build
# 产物：apps/desktop/src-tauri/target/release/bundle/
```

> ⚠️ 当前这条链路**尚未验证产出过 `.msi`**（见 `docs/项目管理/开发任务清单.md` 五、构建与分发）。打包脚本/FFmpeg 内置/GitHub Actions 均未落地，首次打包可能需要补配置。

## 八、常见坑

### 1. 改了 `packages/core` 或 `packages/ui` 的 `.ts` 源码，desktop 没反应
desktop 通过 `workspace:*` 引用的是这两个包的 **`dist/`**（编译产物），不是 `src/`。改源码必须重新构建：

```bash
pnpm build:core && pnpm build:ui
```

频繁改则开 watch 模式，自动重建：

```bash
pnpm -F @myriad-mind/core dev      # = tsc --watch
# 另开一个终端
pnpm -F @myriad-mind/ui dev
```

### 2. 端口 1420 被占直接失败
`vite.config.ts` 里 `strictPort: true`，Tauri 钉死 1420 端口。占用就杀掉占端口的进程，**不能换端口**。

### 3. 首次 Rust 编译很慢
正常，几分钟。之后增量编译快。卡住通常是首次拉 crates 依赖。

### 4. `pnpm dev` 在 apps/desktop 下只起前端
在 `apps/desktop` 目录里，`pnpm dev` = `vite`（纯前端）。要桌面版用 `pnpm dev:desktop`。从**根目录** `pnpm dev` 才是桌面版。

### 5. 用了 npm 而不是 pnpm
报 `workspace:*` 解析失败相关错误。切回 pnpm：`corepack enable && pnpm install`。

## 九、配置文件位置（运行时）

| 文件 | 位置 |
|------|------|
| 应用配置 | `~/.myriad-mind-app/config.json`（Windows: `C:\Users\<用户名>\.myriad-mind-app\`）|
| API Key（DeepSeek 等）| OS 密钥链（Windows 凭据管理器），命名 `myriad-mind/{service}` |
| 应用日志 | `~/.myriad-mind-app/logs/myriad-mind.log`（按 50MB 大小轮转，`KeepSome(2)` 保留最近两份） |
| 笔记输出 | 用户在配置向导选择的输出目录 |
| 知识库索引 | 输出目录下 `.myriad-mind/` |

> API Key **绝不**写入 `config.json`，只存 OS 密钥链，前端只显示脱敏形式。
