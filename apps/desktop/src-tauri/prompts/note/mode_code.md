## 代码项目输出契约

输入材料包含目录结构和关键文件片段。请生成代码项目学习笔记，严格包含以下章节：

1. **项目概览** — 一句话定位、技术栈、运行/构建入口点。用表格呈现项目信息（名称/语言/构建工具/规模/许可证）。
2. **目录结构解读** — 按模块解释职责，不要逐文件流水账。用代码块展示 tree 结构。
3. **核心架构** — 组件关系、数据流、关键调用链。必须包含至少两张 Mermaid 图：
   - 架构总图（graph TD，展示模块层级和依赖）
   - 数据流图（flowchart LR 或 sequenceDiagram，展示数据如何流经系统）
4. **关键文件导读** — 列出 8-15 个最值得读的文件，每个标注：
   - 为什么读（一句话）
   - 推荐阅读顺序（第几步读）
   - 文件角色（入口/配置/核心/辅助）
5. **代码机制详解** — 从材料中提取真实函数名/类型名/配置项，解释：
   - 实现思路和关键设计决策
   - 扩展点和可配置项
   - 与其他模块的交互方式
6. **风险与改进建议** — 从以下维度评估：
   - 测试覆盖（有测试吗？测试什么？）
   - 错误处理（异常路径是否覆盖？）
   - 性能（有无明显瓶颈？）
   - 边界条件和可维护性
7. **学习路线** — 读者接下来应该：
   - 补哪些前置知识
   - 看哪些官方资源
   - 按什么顺序深入
8. **知识关系图** — Mermaid 图展示项目内核心概念及其关联结构。

**重要规则：**
- 不要包含视频时间戳（这是代码项目，不是视频）。
- 来源行格式：`> 📂 原始资源：{路径或 URL}`
- 可靠性评级基于：代码新鲜度、文档质量、测试覆盖。
- 保留所有真实的函数名、类型名、模块名，不要编造或改名。
- 标签维度：技术栈(#Rust) / 框架(#Bevy) / 内容类型(#源码分析) / 难度(#进阶)
