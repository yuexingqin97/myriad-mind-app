# 视频下载后音频提取问题 — 修复建议文档

> 记录时间：task2 后续用户验证阶段  
> 状态：**已按以下建议完成代码修复并验证通过（cargo check + cargo test）**
> 现象：B站/抖音视频下载成功后，`extract_audio` 失败，agent 后续陷入路径错误循环。

---

## 一、现象还原

用户日志片段：

```text
video.mp4 (video_file, ~0 tok): 抖音视频
→ 调用 extract_audio {"video_path": "temp_dir/video.mp4"}
→ extract_audio 失败：FFmpeg 音频提取失败
→ scan_directory {"path": "temp_dir"} 失败：路径不在允许的读取范围
→ read_file {"path": "./temp_dir/video.mp4"} 失败：路径不在允许的读取范围
→ extract_audio {"video_path": "/tmp/temp_dir/video.mp4"} 失败：FFmpeg 音频提取失败
→ transcribe_asr {"audio_path": "/tmp/temp_dir/video.mp4"} 失败：文件不存在
→ fetch_url 抓取 B站页面（成功，但已偏离主线）
```

问题分层：

1. **第一层**：`extract_audio` 返回的 `FFmpeg 音频提取失败` 过于笼统，没有 stderr，无法判断是 FFmpeg 找不到、命令参数错误、还是视频本身无音频。
2. **第二层**：agent 不知道 `video.mp4` 的真实绝对路径，只能凭 `temp_dir/video.mp4` 这种占位符瞎猜，导致后续所有路径类工具都失败。
3. **第三层**：部分短视频（尤其抖音下载下来的片段）可能**本身就没有音频流**，FFmpeg `-map a` 会失败。

---

## 二、根因分析

### 2.1 `extract_audio_ffmpeg` 丢弃了 stderr

当前实现（`apps/desktop/src-tauri/src/commands/pipeline.rs`）：

```rust
let status = std::process::Command::new(ffmpeg)
    .args([...])
    .stdout(std::process::Stdio::null())
    .stderr(std::process::Stdio::null())  // ← 错误信息被丢弃
    .status()
    .map_err(|_| AppError::MissingDependency(...))?;
```

失败时只能返回一句"FFmpeg 音频提取失败"，无法区分：

- FFmpeg 未找到
- 输入文件不存在 / 路径错误
- 视频流没有 audio track
- 编码器缺失
- 输出目录不可写

### 2.2 agent 上下文里没有暴露 artifact 绝对路径

`apps/desktop/src-tauri/src/agent/context.rs` 的 `to_yaml()` 只输出：

```yaml
artifacts:
  - id: video.mp4 | VideoFile | ~0 tok | 抖音视频
```

没有 `path` 字段。agent 看不到 `C:\Users\...\AppData\Local\Temp\myriad-mind\<task_id>\video.mp4`，于是自己编了一个 `temp_dir/video.mp4`，后续工具全部报错。

### 2.3 路径沙箱校验拒绝相对路径和 `/tmp/...`

`ToolContext::resolve_readable` 只允许落在 `temp_dir / artifacts_dir / note_dir / input_root` 内的绝对路径。`temp_dir`、`./temp_dir`、Linux 风格 `/tmp/...` 都会被拒绝，这本身是对的，但 agent 因为看不到真实路径而只能传错路径。

### 2.4 视频无音频流时的处理缺失

抖音下载下来的视频偶尔是纯视频（或音频流为空），`ffmpeg -map a` 会失败。当前没有前置检查，也没有降级策略（例如直接提示"该视频无音频，跳过 ASR"）。

## 三、已完成的代码修复

### 3.1 增强 `extract_audio_ffmpeg` 的错误输出

已修改 `apps/desktop/src-tauri/src/commands/pipeline.rs`：

- `.stderr(Stdio::null())` 改为 `.stderr(Stdio::piped())`。
- 失败后把 stderr 前 500 字符拼进 `AppError::Other`。
- 映射典型错误：
  - `does not contain any stream` / `Stream map 'a'` → "该视频没有音频流，无法提取音频进行 ASR 转写。"
  - 其他 stderr → 直接展示给 agent / 用户。

### 3.2 用 ffprobe 前置检查音频流

已实现在 `extract_audio_ffmpeg` 中：

```bash
ffprobe -v error -select_streams a -show_entries stream=codec_type -of csv=p=0 <video>
```

- 有 `audio`：正常走 ffmpeg 提取。
- 无音频流：直接返回明确错误，避免 ffmpeg `-map a` 的模糊失败。

### 3.3 在 agent 上下文里暴露 artifact 绝对路径

已修改 `apps/desktop/src-tauri/src/agent/context.rs` 的 `TaskState::to_yaml()`：

```yaml
artifacts:
  - id: video.mp4
    kind: VideoFile
    tokens_estimate: 0
    summary: 抖音视频
    path: C:\Users\...\AppData\Local\Temp\myriad-mind\<task_id>\video.mp4
```

并在 YAML 末尾附加提示：

> 当你需要引用 artifact 的文件路径时，必须使用上面列出的绝对 path，禁止使用 temp_dir/...、./...、/tmp/... 等占位符。

### 3.4 路径类工具失败时给 agent 更明确的反馈

已修改 `apps/desktop/src-tauri/src/commands/tools/mod.rs` 的 `resolve_readable`：

错误信息现在会列出当前允许的根目录列表，帮助 LLM 自行纠正路径：

```text
路径不在允许的读取范围内: temp_dir
允许的根目录为：
  - C:\Users\...\AppData\Local\Temp\myriad-mind\<task_id>
  - ...
```

### 3.5 尚未实施（可作为后续迭代）

- 给 `extract_audio` 返回结构化错误码（如 `AUDIO_STREAM_MISSING`），让 agent 更精确地决策。
- `transcribe_asr` 增加文件存在性前置检查。

## 四、与 task2 的关系

本次音频提取问题发生在 task2 迁移完成后的端到端验证阶段。虽然它不属于 Python→Rust 迁移本身，但：

- `extract_audio_ffmpeg` 与 `download_video_ytdlp` 同属 `pipeline.rs`；
- task2 已经改动了 `pipeline.rs`（yt-dlp Cookie、B站路由）；
- agent 工具链（`acquire.rs`、`analyze.rs`、agent context）是迁移后 Rust 后端的核心调用路径。

因此建议把上述修复作为 task2 的后续收尾项，在下一迭代中一并处理。

## 五、用户可立即尝试的绕过方法

在代码修复前，如果只是想验证下载后的流程：

1. 确认下载的 `video.mp4` 是否有声音：用本地播放器打开。
2. 如果没有声音，该视频无法走 ASR，只能让 agent 基于标题/描述/画面生成笔记。
3. 如果有声音但 App 提取失败，通常是 FFmpeg 没找到或路径解析错误；可在设置页重新检测依赖，或把 FFmpeg 路径加入系统 PATH 后重启 App。
